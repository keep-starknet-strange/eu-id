## Decision — the complete OTP closing algebra (sources verified today)

First, a source correction: the truncated phrase "Let Q = q(L,R), which…" is **not in
eprint 2024/2010** (checked both the 2024-12-17 and 2025-12-03 revisions) — it was our
own restatement. Paper §2.3 only gives the abstract Protocol 2.5 + Theorem 2.6. The
normative algebra lives in **draft-google-cfrg-libzk-01 §6.5–6.6** and in both
implementations (C++ `google/longfellow-zk` `lib/zk/zk_common.h`; Rust
`abetterinternet/zk-cred-longfellow` `src/sumcheck/`). They cross-agree. WO-BL3 §4 is
amended accordingly (edits applied).

### 1. How many quadratic constraints per layer
**Exactly one per layer; d total.** Each layer also emits exactly one linear
constraint, plus one global input-binding linear constraint at the very end.
(Confirmed three ways: draft §6.6; C++ `setup_lqc` fills `C.nl` triples; Rust test
asserts `quadratic_constraints.len() == circuit.num_layers()`.)

### 2. `pad_L·pad_R` — a committed product pad element
The per-layer claim pad is a **triple** `[dW_L, dW_R, dW_LR]` with `dW_LR = dW_L·dW_R`
computed by the prover at pad-sampling time and **committed in the Ligero matrix like
any other pad value**. It is not separately opened. The per-layer quadratic constraint
is precisely the tie `dW_L · dW_R = dW_LR`. (Inside Ligero, a quadratic constraint
`(x,y,z)` costs 3 extra tableau rows reduced to linear checks + a per-row product
test — draft §4.4.2.)

### 3. The exact closing constraint set for layer j
Public values: masked transcript (`p̂ᵣ(0), p̂ᵣ(2)` per half-round, `vl̂ = w(L)−dW_L`,
`vr̂ = w(R)−dW_R`), the FS challenges, and the verifier-computed scalar
`Q` = the wiring quad `[α·Q̃_j(r_{j,0},·,·) + (1−α)·Q̃_j(r_{j,1},·,·)]` bound at all of
the layer's round challenges (our "q(L,R)"; C++ `eqq`, Rust `bound_element`).

**Linear (one per layer), over committed pad variables:**
```
  symbolic_claim_terms
  − (Q·vr̂)·dW_L − (Q·vl̂)·dW_R − Q·dW_LR
  =  Q·vl̂·vr̂ − known_claim_part
```
where (`Λ_r = ∏_{r'>r} lag₁(c_{r'})` over the layer's remaining half-rounds):
- coefficient of poly pad `dPᵣ(0)`: `(lag₀(cᵣ) − lag₁(cᵣ))·Λᵣ`
- coefficient of poly pad `dPᵣ(2)`: `lag₂(cᵣ)·Λᵣ`
- coefficient of the *previous* layer's claim pads `dW_L^{j−1}, dW_R^{j−1}`:
  `Λ_{-1}` and `α_j·Λ_{-1}` (absent for layer 0, whose incoming claims are public)
- `known_claim_part` = the same recursion applied to the public masked values.
The recursion generating these (normative, draft §6.6): per half-round
`sym_p1 = sym_claim − sym_p0`, then
`sym_claim ← lag₀(c)·sym_p0 + lag₁(c)·sym_p1 + lag₂(c)·sym_p2`.

**Quadratic (one per layer):** `dW_L · dW_R = dW_LR`.

**Global input binding (once):** draw `γ`; with `eq2 = bind(EQ,G₀) + γ·bind(EQ,G₁)`:
`Σᵢ eq2[i+npub]·w_priv[i] − dW_L^{last} − γ·dW_R^{last} = −Σᵢ eq2[i]·x_pub[i] + claim₀ + γ·claim₁`.

### 4. Paper vs draft vs implementations — which is authoritative
- **Draft-01 has a typo** in the closing RHS: it prints `Q·vl̂·vl̂`. Both
  implementations compute `Q·vl̂·vr̂` (C++ `finalize`: `mulf(eqq, mulf(wc[0], wc[1]))`;
  Rust: `bound_element * proof_layer.vl * proof_layer.vr`). **The code is
  authoritative**; use `vl̂·vr̂`.
- Sign convention: paper says `masked = value + pad`; draft/code use `value − pad`.
  Either is sound; **use `value − pad`** to match the reference test vectors.
- The two implementations interoperate on shared test vectors; treat the Rust port's
  `src/sumcheck/mod.rs::run_protocol` + `src/sumcheck/constraints/mod.rs` as the
  line-by-line reference for BL3 §4.

### 5. Consequential BL2/BL3 amendments (applied to the WOs)
- **Round polynomials are degree ≤ 2, not 3.** Our `g_j` is (multilinear wiring) ×
  (multilinear Ṽ) per variable ⇒ degree 2. Longfellow evaluates at `{0, 1, 2}` and
  transmits **only `p(0)` and `p(2)`** — `p(1) = claim − p(0)` is implied, never sent,
  and the `p(0)+p(1)=c` check disappears into the recursion above. WO-BL2 §2/§4
  amended (round-poly mixes are `p(0), p(2)` pairs). This halves round-poly bandwidth
  and pad count.
- **OTP pads per half-round are pairs `[dP(0), dP(2)]`**, not triples — WO-BL3 §4
  step 1 amended; claim pads are the triples of §2 above.
- The masked final operands are `vl̂, vr̂` only (two per layer, from the two-claim
  fold), not a per-evaluation list.

Proceed with the OTP/Ligero integration on this basis; the §3 parameter computation
from answers/Q-020.md is unchanged by any of this.
