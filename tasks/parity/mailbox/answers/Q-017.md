### Answers to your four items

1. **Binding SHA/digest-bind committed `z` to coprocessor claims:** `z` becomes a
   public input on both sides. The coprocessor binds its witnessed limbs to the
   public felt via C1/C2 (already in WO-G4 — no new constraints). The M31 side keeps
   proving `z = SHA-256(C)` in-circuit by re-targeting the digest-bind bridge to the
   public `z` — reuse the `PublicDigestBind` component already shipped in
   `eu_id_prover::mdoc` (binds public 32 bytes onto the SHA `Sha256Digest` LogUp
   relation). No MLE opening, no MAC, no new binding component.

2. **Do `r` and `s` bind through the same argument in v1?** Yes, trivially: they are
   public statement values absorbed once into the shared channel and checked by the
   verifier against its expected statement; in-circuit they are bound by C1/C2 like
   `z`. No separate mechanism.

3. **Transcript messages and exact ordering** (normative; deviation = mailbox):
   1. M31-side commitments/publics in their existing monolith order (unchanged).
   2. Coprocessor domain tag `b"eu-id-ec-coproc-sumcheck-v1"` + circuit shape
      (`d`, all `w_j`) — BL2 §4 line 1 as written.
   3. The full public ECDSA statement, 32-byte BE per element, fixed order per
      signature: `z, r, s, Qx, Qy`, then blind index `i` and blind points
      `B.x, B.y, D.x, D.y` (Q-022). All signatures (credential, then device/nonce)
      before any commitment.
   4. The BL3 Ligero root `com`.
   5. BL2 sumcheck per its §4 (per layer: `α_j`; per half-round: `p(0), p(2)` — note
      the Q-018 amendment, `p(1)` is implied and never mixed; then the next-layer
      claims).
   6. BL3 opening challenges (proximity vector `γ`, then the `t` column indices).
   Invariant to test: every coprocessor challenge is drawn from state that has
   absorbed 1–4.

4. **Verifier-side rejection conditions and required negative tests:** the five
   conditions in G3 §3, each with one targeted test: (a) statement element flipped
   (reject before any STARK work), (b) `z` consistent with the statement but not with
   the credential bytes (global LogUp imbalance — this is the credential↔signature
   attack test), (c) one tampered sumcheck round / Ligero column (coprocessor
   reject), (d) two absorbs swapped in a doctored prover (challenge divergence
   reject), (e) off-profile BL3 parameters or M31 PCS config (reject before
   verification).
