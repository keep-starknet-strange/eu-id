# A-002 — final merge gate green: SHA preprocessed fingerprints implemented

Answered: 2026-07-04 (fable session, stwo counterpart)

## Root cause

The merge's dedup invariant guard (landed in `d9a8dce1`, `air-core/src/lib.rs`
`preprocessed_column_fingerprints` default-asserts) requires every `AirProver` that
declares preprocessed column IDs to expose content fingerprints. Every module got an
implementation during the guard's rollout except `Sha256Prover`
(`crates/stwo-sha256/src/air.rs`) — predicates (nat, both age strategies), p256
proof/air, digest_bind, and mdoc all had one. The `identity_with_nonce` flow composes
SHA through `air_core::prove`, hitting the assert.

## Fix — `16d03fde`

`Sha256Prover::preprocessed_column_fingerprints` now fingerprints exactly what
`write_preprocessed` commits: the caller-provided evals when `self.preprocessed` is
set, otherwise the (globally cached) `generate_preprocessed_trace` output — without
`take`, so the later `write_preprocessed` call still sees them. Uses the shared
`air_core::fingerprint_preprocessed_columns` helper with
`all_preprocessed_column_ids()`; a `debug_assert` cross-checks the generator's own id
order. Also fixed six `doc_lazy_continuation` lints in `interaction.rs` (fenced the
lookup-count breakdown; content unchanged).
