# stwo-p256 Crate Reorganization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reorganize `crates/stwo-p256` into a clean domain-module tree and delete all code outside the live monolithic proof path, with byte-identical live behavior.

**Architecture:** Two phases. **Phase 1** deletes the redundant *slice* proof system, the dormant `Selector*` lookup AIR, and two compile-disabled constraint bodies — all confirmed dead by a reachability pass from `prove/verify_current_air_monolithic` + `relation_balances()`. **Phase 2** moves/splits the surviving live code into `field/ curve/ range_checks/ gadgets/ components/<each: air·trace·interaction> proof/`, splitting the three monoliths (`projective_air.rs` 6.7k, `prepared_table.rs` 3.7k, `proof.rs` 6.4k) along their seams. Every change is a pure relocation/deletion — no logic edits, no reordering of trace reads / constraint or relation emissions / component registration.

**Tech Stack:** Rust, stwo / stwo-constraint-framework (circle-STARK AIR), SimdBackend, Blake2s Merkle channel. Build/test via `cargo` (use `rtk cargo …` per repo convention).

**Reference:** design spec `docs/superpowers/specs/2026-06-08-stwo-p256-reorg-design.md`. Soundness findings (explicitly out of scope here) in `crates/stwo-p256/docs/soundness-audit.md`.

**Verification model (refactor, not feature):** there is no "write a failing test" loop. The existing test suite + the relation-balance assertions are the behavior gate. After every task: `rtk cargo build -p stwo-p256 --all-targets` and `rtk cargo test -p stwo-p256` must stay green, then commit. The Phase-0 baseline is the reference; the final gate re-confirms identical relation balances.
